**`capabilities.density` reported `not-applicable` for 125 of 145 component families, and nobody
had decided that for any of them.**

Source inspection can prove `supported` — the component reads a density metric. It cannot prove
`not-applicable`, because that is a claim about design intent: that this component would look no
different at any density and never should. The detector returned it anyway as the fallback for
anything that did not participate. And because the contract ratchet counts only `unknown`, the
manifest showed a density review backlog of **zero** while 86% of the library was making an
undecided claim.

- **`src/contracts/density.ts` now names the four values and who is allowed to say each one.**
  `DENSITY_APPLICABILITY` is the vocabulary; `DERIVABLE_DENSITY_APPLICABILITY` is the subset
  derivation may emit — `supported` and `unknown`, nothing else. `not-applicable` and
  `unsupported` require an explicit registry declaration, which is a review with a name on it.
- **The 20 families that participate today are locked per slug.** `check:contract` ratchets an
  aggregate `unknown` count, which cannot distinguish "component A lost density support and
  component B gained it" from "nothing changed". The per-slug list fails by name.
- **DensityProvider has tests for the two behaviours the docs claimed and nothing asserted:** that
  a `compact` subtree nests inside a `comfortable` document (both the inherited attribute and the
  context), and that unmounting removes the document attribute when there was none to restore.
- **A test that the density tokens actually differ per mode.** jsdom applies no stylesheet and does
  no layout, so this asserts the generated bytes: every contract metric is declared under every
  mode, and no two modes declare the same value — which is what would silently make a
  "density-aware" component render identically in both.
- `docs/standards/density.md` documents the four-value table and the derivation rule.

**Residual, stated plainly:** the manifest still reports 125 `not-applicable`. Flipping the
detector's fallback and declaring the defensible cases in the registry touches
`scripts/lib/component-source.mjs`, `scripts/check/component-contract.mjs` and
`src/manifests/component-registry.ts`, and moves the coverage baseline. This changeset lands the
contract and the guards; the enforcement is a separate, coordinated change.
